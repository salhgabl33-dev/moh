# هلا نت 2027.3 — الدخول والتذكّر والتنقّل

الحزمة مهيأة لـ **CCR2116 / RouterOS 7.25** مع **User Manager خارجي على RB1100x4 / RouterOS 6**. البروفايل الرئيسي المقصود هو **hashedSpeed** وفق تأكيدك؛ يحمل default وUM10USER كود الدخول نفسه كي تعمل الصفحة مع البروفايل الذي يختاره RADIUS حالياً. لا يغير ذلك مجموعة RADIUS أو مستخدمي User Manager أو أرصدتهم.

**لم تُنفّذ على راوتر فعلي**. الاختبارات تفحص الواجهة وبنية المصادر ولا تثبت تشغيلها في شبكتك. ابدأ بكرت اختبار واحفظ قيم البروفايلات السابقة.

## الملفات وموضعها

| الملف | الاستخدام |
| --- | --- |
| on-login-hashedSpeed.rsc | محتوى On Login في hashedSpeed |
| on-login-default.rsc | محتوى On Login في default، بالجسم نفسه |
| on-login-UM10USER.rsc | محتوى On Login في UM10USER، بالجسم نفسه |
| on-logout.rsc | محتوى On Logout المشترك |
| configure-roaming.rsc | إعداد مشغّل يثبت الأحداث والتذكّر بعد فحوص ونسخ احتياطية |
| diagnose-roaming.rsc | تشخيص للقراءة فقط |
| kick-duplicate-device.rsc | إصلاح يدوي لجلسة مكررة، وليس طرداً تلقائياً أثناء التنقّل |
| cleanup-stale.rsc | تنظيف دوري اختياري لموارد HN27 دون جلسة نشطة |
| on-logout-200-safe.rsc | خروج محدود اختياري لبروفايل 200 القديم فقط |

ملفات أحداث On Login وOn Logout تعتمد على متغيرات العميل التي يوفّرها الهوتسبوت. تُلصق في حقول الأحداث أو تُثبت بملف الإعداد؛ لا تُستورد وحدها في Terminal.

## ترتيب التركيب

1. احفظ الصفحة الحالية وحقول الأحداث وإعدادات Cookie والمهلات. جرّب في وقت يسمح بالتراجع وبحساب اختبار، ولا تجمع الكود القديم والجديد في الحقل نفسه.
2. ارفع **محتويات مجلد hotspot/** إلى مجلد مستقل مثل hotspot-2027 على CCR، ثم اختر مساره الصحيح في HTML Directory لخدمة المشتركين المقصودة.
3. ارفع مجلد **routeros/** كاملاً إلى Files. يفترض ملف الإعداد أن المسار هو routeros/. إذا رفعته داخل flash/ عدّل متغير directory في ملف الإعداد إلى flash/routeros/ واستعمل مسار الاستيراد الفعلي.
4. شغّل التشخيص أولاً:

    /import file-name=routeros/diagnose-roaming.rsc

يمكن وضع IP الهاتف الفعلي في متغير phoneIP داخل ملف التشخيص لتحديد خدمة الهاتف وواجهتها وServer Profile وعدد سجلات MAC ذات الصلة. يبقى الملف للقراءة فقط.

5. بعد مراجعة التشخيص والنسخ السابقة، يمكن تشغيل الإعداد:

    /import file-name=routeros/configure-roaming.rsc

يفحص الإعداد وجود hsprof1 مع RADIUS والمحاسبة وطريقتي cookie وmac-cookie المفعّلة أصلاً، ويتحقق من ملفات الدخول بإصدار 2027.3. ثم يحفظ محلياً HN27-user-profiles-before-roaming.rsc وHN27-server-profiles-before-roaming.rsc إذا لم يكونا موجودين، قبل تغيير الحقول. هذه نسخ خاصة قد تتضمن مصادر سكربتات إدارية.

يركب الأحداث على hashedSpeed وdefault وUM10USER إن وجد الأخير، ويفعّل add-mac-cookie=yes وmac-cookie-timeout=30d ويضبط idle-timeout=none وsession-timeout=0s. يرفع http-cookie-lifetime إلى 30 يوماً في **hsprof1 فقط**. يحتفظ بمهلات keepalive وshared-users وACTIVE وطرق الدخول وحدود RADIUS الحالية، ولا يقطع الجلسات الحالية.

يتوقف عند فشل الفحص. الإعداد ليس معاملة ذرية؛ إذا وقع خطأ بعد بعض التغييرات، استعد الحقول المتأثرة عبر WinBox من نسخك السابقة. لا تستورد تصديراً كاملاً اعتباطياً فوق إعدادات حية. النسخ الاحتياطية الأولى لا تُستبدل عند تكرار الإعداد.

## شرط التنقّل الصحيح

المقصود **الهاتف نفسه بين نقاط الواي فاي**. استمرار الجلسة يتطلب تقديم شبكة المشتركين نفسها فعلاً: SSID وإعداد أمان متناسقان، وربط Bridge/AP دون NAT مستقل، وVLAN وخدمة HotSpot وبوابة وDHCP متوافقة، وعنوان MAC ثابتاً للهاتف على تلك الشبكة. يمكن استعمال عنوان خاص ثابت لهذه الشبكة بدلاً من عنوان متغير باستمرار. لا يلزم إلغاء عزل المشتركين أو دمج بقية VLANs.

في هذه الحالة تبقى الجلسة، أو يُعاد الدخول تلقائياً عبر MAC Cookie صالح. لا تحتاج طرداً عند كل انتقال. إذا دخل الهاتف HotSpot مستقلاً أو تغيّر MAC أو ظهرت له سجلات Host متعددة، فلا يضمن تشابه الرنج استمرار الدخول. تسريع الانتقال اللاسلكي يعتمد أيضاً على نقاط الوصول وإعدادها.

## ما يثبته التصدير عن 192.168.20.0/24

- يوجد 192.168.20.1/24 على الجسر OUT، لكن DHCP لذلك الجسر يستخدم OUT-POOL بعناوين 172.26.x.x، ولا تظهر شبكة DHCP مطابقة لـ192.168.20.0/24.
- توجد **255 خدمة HotSpot**: hotspot1 على OUT يستعمل hsprof2، و254 خدمة على VLANs تستعمل hsprof1.
- hsprof1 مفعّل لـRADIUS. لم يُذكر تفعيل RADIUS في hsprof2 الذي يعرض صفحة أخرى. يضبط الإعداد خدمة RADIUS المعروفة ولا يحوّل hsprof2 أو يعيد توزيع الشبكات.

لذلك لا يصح استنتاج HotSpot واحد من عنوان OUT وحده. إذا كان الهاتف يعمل عبر hsprof2 أو يتغير Server/VLAN عند تنقله، فإعداد تذكّر hsprof1 وحده لن يحل ذلك؛ يجب توحيد مسار ذلك الـSSID على نقاط الوصول والخدمة الفعلية. الحزمة لا تخمن توصيلات نقاط الوصول ولا تغير الجسر أو DHCP أو VLAN.

## السرعات وتذكّر الاختيار

قيم الصفحة والسكربتات موحّدة مع كود hashedSpeed الذي أرسلته، بترتيب **رفع/تنزيل**:

| الخيار | القيمة |
| --- | --- |
| اقتصادية | 1M/3M |
| متوسطة — الافتراضية | 2M/4M |
| عادية | 2M/6M |
| عالية | 5M/10M |
| عالية جداً VIP — الخضراء الخامسة | 10M/20M |

ترسل الصفحة domain=السرعة|*yes** أو السرعة|*no**. قد يغيب domain عند إعادة الدخول بواسطة Cookie؛ لذلك يحتفظ الراوتر بالاختيار الصالح الأخير للجهاز والكرت في قائمة مستقلة غير مستخدمة للمصادقة اسمها HN27-PREFS.

تضم الذاكرة MAC ومعرّف الكرت المرمّز وسرعة وعلامة تحديثات، دون كلمات المرور. ترميز hex قابل للعكس؛ تعامل مع هذه البيانات خصوصياً. لا تمنح القائمة اتصالاً ولا تتجاوز RADIUS أو الرصيد.

الذاكرة محدودة بعشرة آلاف سجل وبمهلة 30 يوماً من آخر دخول. سجلات Address List ذات المهلة تُحفظ في RAM وتختفي عند إعادة التشغيل؛ ليست تخزيناً دائماً. إذا غابت الذاكرة وdomain، يُستعمل سقف 2M/4M وتظهر رسالة في Log. يمكن إعادة اختيار السرعة من الصفحة بعد تسجيل الخروج.

## الدخول والخروج والطوابير

لا يوجد في On Login طرد تلقائي من Active أو إزالة Cookie. يحدد max-limit سقف السرعة ويستعمل SPEED/SPEED من FQ-CoDel عند وجوده، وإلا default-small/default-small. يبقى limit-at=0/0 دون وعد بحصة مضمونة لكل عميل.

يتبنى Queue العميل القديم في موضعه فقط عند تطابق IP والهدف والنوع وParent والعلامة المعروفة HALA-HS-SPEED أو Cards أو 10-USERS. يتوقف عند التعارض ولا يحذف طوابير إدارية بالعنوان وحده. يحتفظ بالترتيب افتراضياً؛ moveToTop خيار إداري منفصل يؤثر في سياسة المطابقة.

افحص سمة Mikrotik-Rate-Limit القادمة من User Manager والطوابير المنافسة؛ لا تجمع مصدرين متعارضين للسرعة. FastTrack يتجاوز Simple Queues؛ الموجود في تصديرك مخصص لـTCP/8888 وUDP/53، لذلك لا يضيف الحل أمراً لتعطيله على الراوتر كله. تُحفظ حدود الكروت والمحاسبة، ولا تُصفّر لتشغيل القالب.

ينظف On Logout طابور العميل وقائمة التحديثات المملوكين له بعد فحوص للجلسات النشطة. لا يحذف ذاكرة الاختيار أو Cookie المصادقة؛ يترك أسباب إنهاء الجلسة لنظام HotSpot. تقلل الفحوص سباقات إعادة الاتصال، لكنها ليست قفلاً أو معاملة ذرية.

قاعدة RAW الأصلية المرتبطة بـ*yes** وStop_update محفوظة. تُنقل عضوية العميل ذات تعليق HALA-HS-UPDATES إلى ملكية HN27. تبقى العضويات الخالية من التعليق دون تغيير افتراضياً؛ يمكن تفعيل migrateLegacyUpdateEntries مؤقتاً بعد مراجعتها ثم إيقافه بعد الانتقال.

## متى يُطلب تسجيل الدخول مجدداً؟

التذكّر مدته 30 يوماً، وليس ضماناً دائماً. قد يلزم الدخول عند انتهاء Cookie أو صلاحية الاشتراك أو حصص RADIUS، أو تغيير MAC/الشبكة، أو مسح Cookie، أو رفض المصادقة. تبقى أرصدة البيانات والوقت والمحاسبة لدى User Manager، وتظل حدود RADIUS ومهلاته مقدمة على الإعدادات المحلية. لا توجد IP Binding bypass أو مصادقة عامة بالـMAC تتجاوز الكرت.

يرسل زرّا تسجيل الخروج وخروج ونسيان الكرت **erase-cookie=on** لإنهاء الدخول التلقائي المقصود. الثاني يمسح أرقام الكروت المحفوظة محلياً أيضاً. حفظ رقم الكرت في المتصفح لا ينفّذ مصادقة تلقائية ولا يحفظ كلمة المرور.

إزالة جلسة من Active تسبب admin-reset وقد تحذف MAC Cookie؛ لذلك ملف kick-duplicate-device.rsc **إصلاح يدوي فقط**. يحتاج IP وServer لجلسة واحدة مؤكدة يحتفظ بها، ويقصر الحذف على جلسات الكرت وMAC نفسيهما مع إعادة فحص معرّف الجلسة. لا تضعه في On Login أو Scheduler، وقد يحتاج الهاتف إلى دخول ناجح جديد بعد استعماله.

أُزيل الطرد الآلي من default عمداً لتوافق هدف التنقّل، مع إبقاء قيمة shared-users الأصلية. إذا أردت فرض جهاز واحد للكرت، فراجع Port-Limit في User Manager وسياسة RADIUS؛ لا يستنتج اسم البروفايل وحده هذا الحد.

## فحص قبل التعميم والتراجع

1. اختبر كرتاً صحيحاً وخاطئاً، وقارن سرعة Queue واستهلاك الكرت ببيانات User Manager.
2. انتقل بالهاتف نفسه بين نقطتين؛ يجب ألا يتغير MAC أو مسار HotSpot المقصود.
3. اختبر إعادة اتصال قصيرة وانتهاء keepalive؛ تحقق من MAC Cookie ومن اختيار السرعة المحفوظ عند غياب domain.
4. اختبر انتهاء رصيد/صلاحية كرت تجريبي: يجب أن يرفض User Manager الاستمرار أو الدخول التلقائي.
5. اختبر زري الخروج؛ يجب أن يتوقف الدخول التلقائي حتى إدخال الكرت مجدداً.
6. راجع Log لرسائل HN27، ولا تعمم النقل إذا ظهر تعارض طوابير أو بروفايل مختلف للهاتف.

للتنظيف الدوري الاختياري، ضع محتوى cleanup-stale.rsc في System → Scripts باسم HN27-cleanup، واستدعِه بمهمة واحدة كل خمس دقائق. يزيل الموارد المملوكة غير النشطة، ولا يمس HN27-PREFS أو الكروت. للتراجع استعد الصفحة والحقول السابقة عبر WinBox من نسخك.
