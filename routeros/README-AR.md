# سكربتات User Profile المتوافقة مع هلا نت 2027

هذه سكربتات موجهة للترتيب الذي وصفته: **CCR2116 بنظام RouterOS 7 يشغّل الهوتسبوت، وRB1100x4 بنظام RouterOS 6 يشغّل User Manager عبر RADIUS**. راجعت صياغتها ومجال تعديلها وفق توثيق MikroTik. **لم تُنفّذ على راوتر فعلي**؛ يلزم التحقق من إعدادات RADIUS والطوابير الموجودة عندك قبل تعميمها.

تُوضع سكربتات الدخول والخروج والتنظيف على **CCR2116**. يستمر **RB1100x4** في المصادقة والمحاسبة وصلاحية الكروت وأرصدة البيانات والوقت؛ لا يتضمن الحل أوامر تصفير أو حذف تلك الأرصدة أو مستخدمي User Manager.

## الملف الصحيح للصفحة

ملف RAR المعاد إرفاقه مطابق بايتياً للأصل القديم ذي أربع سرعات، وليس إصدار 2027.2 بالشعار الذهبي والخمس سرعات. ارفع محتويات مجلد `hotspot/` من حزمة ZIP الحديثة إلى مجلد مستقل. لا ترفع ملفات هذا المجلد `routeros/` مكان صفحات الدخول.

## شروط تشغيل اختيار السرعة

ترسل الصفحة حقل `domain` بصيغة `2M/4M|*no**` مثلاً. توثق MikroTik خاصية `domain` في سجل HotSpot Active بأنها للاستخدام مع RADIUS. بنيتك تستخدم RADIUS بالفعل، لكن يجب التحقق من وصول القيمة نفسها عبر إعدادات الدخول الحالية؛ وجود RADIUS وحده لا يثبت هذا.

بعد الدخول بكرت اختبار، افتح **IP → Hotspot → Active** وافحص `domain` للعميل، أو شغّل أمر القراءة التالي، مستبدلاً عنوان المثال بعنوان الجهاز الفعلي:

```routeros
/ip hotspot active print detail where address=192.0.2.27
```

ينبغي أن تظهر قيمة مثل `3M/6M|*yes**` عند اختيار «عادية» مع منع التحديثات. إذا كانت فارغة أو غير مدعومة، يطبق السكربت الافتراضي المحدود `2M/4M` ويسجل تحذيراً في **Log**؛ **لن ينفّذ اختيار الزر في هذه الحالة**. لا يكفي تغيير الواجهة لحل غياب هذه البيانات؛ يلزم معرفة نوع الحسابات وإعداد RADIUS أو اختيار سياسة سرعات تعتمد على البروفايلات.

تستخدم السكربتات قائمة قيم مسموحة مطابقة للصفحة: `1M/2M` و`2M/4M` و`3M/6M` و`4M/8M` و`8M/16M` بترتيب **رفع/تنزيل**. عند تعديل قيم الواجهة لاحقاً يجب تعديل القائمة المسموحة في السكربت أيضاً.

## وضع السكربتات بالترتيب

1. احتفظ بنسخة نصية من سكربتي البروفايل الحاليين وإعداداته. جرّب على **User Profile مستقل وحساب اختبار واحد**، مع إبقاء الصفحة القديمة متاحة للتراجع.
2. من **IP → Hotspot → User Profiles** افتح البروفايل المعني، ثم **Scripts**. لا تخلط هذا المسار مع **Server Profiles** المستخدم لاختيار HTML Directory.
3. على CCR2116، اختر User Profile الذي تستخدمه جلسة RADIUS الفعلية. قد يحدده User Manager بسمة `Mikrotik-Group` إن كنت تستخدمها؛ لا تفترض اسماً محدداً. انسخ كامل محتوى `on-login.rsc` إلى **On Login**، وكامل محتوى `on-logout.rsc` إلى **On Logout**. هذه محتويات حقول الأحداث؛ لا تنفذ `/import` لهذين الملفين في Terminal، لأن متغيرات العميل لا تكون متاحة هناك.
4. لا تجمع الكود القديم والجديد في الحقل نفسه. قد تتضمن السكربتات القديمة منطق فوترة أو RADIUS مهماً؛ لا تستبدلها لحسابات الإنتاج قبل مراجعة ذلك المنطق ودمجه إن احتجته.
5. لإنشاء Queue واحد مسؤول عن الحد، يلزم ألا يوجد حد منافس آلي أو قديم للعميل. افحص **Rate Limit** للبروفايل، وسمات RADIUS مثل `Mikrotik-Rate-Limit`، والـQueues الحالية. لا تحذفها عشوائياً ولا تغيّر حدود المشتركين المدفوعة لمجرد تشغيل القالب.
6. يجب استثناء حركة عملاء الهوتسبوت من **FastTrack** إذا كان يعبرها؛ FastTrack يتجاوز Simple Queues. لا يحتوي هذا الحل أمراً لتعطيله على الراوتر كله.
7. تحقق من أن النظام يسمح للحدث بالوصول إلى HotSpot Active والـSimple Queues وFirewall Address Lists. لا يتضمن الحل تغييرات تلقائية لصلاحيات الإدارة.

عند تجربة هذا التصميم، تكون صلاحية الكرت ورصيد البيانات والوقت لدى User Manager، ويحدد سكربت CCR سقف السرعة المختارة. لذلك ينبغي أن يكون **Rate Limit** في بروفايل الاختبار على CCR فارغاً، وأن تتأكد من عدم إرسال حد سرعة منافس من User Manager لذلك الحساب التجريبي. لا تحذف حدود البيانات والوقت. إذا أردت أن يبقى User Manager هو المسؤول عن سرعة كل اشتراك، فلا تجمع معه هذه الإدارة المستقلة للسرعة قبل تكييفها مع سياسة اشتراكاتك.

## الإضافة والتحديث والحذف

- ينشئ الدخول Queue مستقلاً باسم `HN27-عنوانIP`، ويحدّثه عند وجوده بدلاً من حذفه وإعادة إنشائه في كل اتصال. تعليق الملكية يتضمن IP وMAC واسم المستخدم.
- إذا وجد اسماً محجوزاً `HN27-...` لا يحمل تعليق الملكية الصحيح، يتوقف ويكتب خطأ بدلاً من الاستيلاء على Queue إداري آخر.
- يحدد `max-limit` سقف السرعة، ويترك `limit-at=0/0` دون وعد بحصة مضمونة لكل عميل. نوع Queue المستخدم هو `default-small/default-small` المدمج.
- يحافظ افتراضياً على ترتيب الـQueue الموجود، ويضيف الجديد في نهاية القائمة. لا ينقل طوابير الشبكة الأخرى ولا يزعم توزيعاً عادلاً للسعة.
- الخيار `moveToTop` داخل On Login مضبوط على `false`. يمكن تغييره إلى `true` بعد مراجعة تصميم الطوابير إذا أردت نقل Queue العميل إلى البداية. قد يؤثر ذلك في حدود التجميع وسياسة أول مطابقة؛ إذا بقيت Queues عامة قبله فقد تتقدم هي عليه. هذا قرار يعتمد على بنية شبكتك.
- عند طلب `*yes**` يضيف أو يحدّث عنصراً مملوكاً في قائمة `*yes**`، وينظف النسخ المكررة المملوكة فقط. عند `*no**` يزيل عناصره في هذه القائمة فقط. لا يحذف عضويات IP في القوائم الأخرى أو العناصر الإدارية غير المملوكة.
- يفحص الخروج وجود جلسة نشطة على IP قبل الحذف، ويحذف فقط تعليق الجهاز والمستخدم المغادرين. هذا يقلل حذف موارد جلسة أحدث؛ الأوامر ليست معاملة ذرية، ولا يمكن ضمان غياب سباق إعادة دخول المستخدم نفسه تماماً.
- السكربتات مخصصة لعملاء IPv4 بعناوين فريدة؛ لا تفترض دعم شبكات VRF ذات العناوين المتداخلة أو تحديد IPv6.

## خيار منع التحديثات

القائمة `*yes**` متوافقة مع اسم القائمة الذي كان يستعمله السكربت المرفق الأصلي. هي **علامة فقط**؛ لا تمنع تحديثات جوجل وحدها. يلزم وجود قواعد مناسبة في شبكتك تستخدم `src-address-list="*yes**"`. لم تُضف قواعد حجب عامة، لأن التحديثات المشفرة والعناوين المشتركة قد تتداخل مع خدمات أخرى. وجود العنصر في القائمة لا يثبت نجاح الحجب.

## تنظيف ما بقي بعد انقطاع الكهرباء

قد لا يقع حدث Logout عند انقطاع الكهرباء أو إعادة تشغيل مفاجئة، بينما تبقى الموارد الثابتة. الخيار الإضافي `cleanup-stale.rsc` يزيل موارد HN27 التي لا يقابلها عميل نشط. يفحص بادئة الاسم وتعليق الملكية ولا يلمس العناصر الأخرى.

يمكن لصق محتواه في **System → Scripts** باسم `HN27-cleanup`. ولتشغيله دورياً، أضف مهمة في **System → Scheduler** بفاصل `00:05:00`، ومحتوى **On Event**:

```routeros
/system script run HN27-cleanup
```

اختر بدء المهمة بعد إقلاع الراوتر بمدة كافية، مثل دقيقة، وامنح المهمة والسكربت صلاحيات القراءة والكتابة اللازمة فقط وفق سياسة الإدارة لديك. المهمة اختيارية، وليست مركّبة تلقائياً. اختبرها يدوياً أولاً ولا تنشئ مهام مكررة.

## فحص مختصر قبل التعميم

1. دخول صحيح وخاطئ، وفحص حقل `domain` الفعلي؛ غيّر السرعة بعد الخروج وأعد الدخول.
2. تحقق من اسم Queue والتعليق و`target` و`max-limit` في WinBox، ثم اختبر المرور الفعلي مع مراعاة FastTrack والطوابير المنافسة.
3. فعّل خيار التحديثات وألغِه مع إعادة الدخول؛ تحقق من القائمة ومن قاعدة الحجب الفعلية، وليس شكل المفتاح فقط.
4. سجّل الخروج وتأكد من إزالة موارد HN27 للعميل، مع بقاء Queues والقوائم الإدارية الأخرى.
5. جرّب إعادة الدخول السريعة، وتبديل الجهاز أو الكرت، والتنظيف الدوري بعد انقطاع تجريبي، وراجع Log للرسائل التي تبدأ بـ`HN27`.
